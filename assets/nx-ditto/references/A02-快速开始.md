# A02 · 快速开始

## 1. 先确认 Ditto 在跑、库在不在

```bash
node bin/ditto.mjs clip info
```

输出长这样：

```
数据库   : C:\Users\<你>\AppData\Roaming\Ditto\Ditto.db
来源     : %APPDATA%\Ditto
大小     : 749.1 MB（最后写入 2026-11-02T16:54:00.408Z）
条目     : 1640 条
图片     : 303 张 / 743.1 MB
文本     : 2649 条
时间跨度 : 2025-12-03 19:10:44 → 2026-11-03 00:54:00
```

**报错怎么办**——错误文案里会写清查找顺序：

| 情况 | 原因 | 怎么办 |
| --- | --- | --- |
| `Ditto 数据库不存在` | Ditto 没装，或装完从没运行过 | 装 Ditto 并启动一次，它会建库 |
| `Ditto 数据库不存在` | Ditto 是便携版，库在 exe 旁边 | 工具会自动找；找不到就用 `NX_DITTO_DB` 指过去 |
| 能读到但条目是 0 | 刚启动，还没复制过东西 | 复制点东西再查 |

指定别的库：

```bash
# Windows PowerShell
$env:NX_DITTO_DB = "D:\tools\Ditto\Ditto.db"
node bin/ditto.mjs clip info
```

## 2. 第一条查询

```bash
node bin/ditto.mjs clip list --limit 10
```

```
ID     时间                 类型  大小    格式                    预览
-----  -------------------  ----  ------  ----------------------  --------------------------------
34600  2026-11-03 00:54:00  text  1.0 KB  CF_TEXT|CF_UNICODETEXT  /server-cli-web-scaffold ...
34595  2026-11-03 00:38:13  image 27.4 KB CF_DIB                 CF_DIB
```

- `ID` 是条目的主键，后面 `clip show` / `clip image` 都用它
- `预览` 字段对图片条目的显示的是格式名，不是内容
- 中文预览的对齐是对的（按显示宽度算的，不是按字符数）

## 3. 取一条图片

```bash
node bin/ditto.mjs clip image 34595 --out D:\shots
```

输出：

```
图片已保存: D:\shots\clip-34595-20261103-003813.png（100x70，6.4 KB）
```

打开这个 PNG 应该能看到复制时的原图。原始数据是 CF_DIB 位图，
这一步是「还原」，不是「转格式存了个字节流」。

## 4. 起面板

```bash
node bin/ditto.mjs serve
```

浏览器打开后顶部多一个「剪贴板」页：库概况、类型筛选、图片画廊、历史列表。
面板上的每个操作都有等价 CLI 命令（页面底部有提示行）。

开发期用 `pnpm dev`（vite + serve 两个进程，热更新）。

## 5. 给 agent 用

每条命令都支持 `--json`，输出纯 JSON：

```bash
node bin/ditto.mjs clip list --limit 5 --json
```

装成 skill（本项目只能在项目根目录内安装）：

```bash
node bin/ditto.mjs skill install nx-ditto
```
